# 第二批技能的五条 UI 缺口：补齐方案

> 2026-08-04。承接 `2026-08-04-batch-2-hardening.md` §2.1 的 A1–A5。
> 结论先说：**五条缺口收敛成三个改动点，全部零引擎改动**——要的信息早就在快照里，
> 缺的只是「画出来」和「说清楚」。

---

## 0. 先回答：A4「神授『先问一句』没说来源」是什么意思

神授♥5 的执行面是这样的：不属于那五种「一定要摸」的情形时，引擎不直接给他摸牌，
而是先开一个窗口问「要不要摸」。这个窗口（`drawOffer`）是**和合纵/连横②共用的**——
两边问的是同一句话，所以当初刻意没在文案里提触发者：

```
可以摸 2 张再弃 2 张，也可以这次不摸
```

「没说来源」= **这句话没告诉玩家这个选择权是哪张技能给的**。后果有两层：

1. **玩家不知道为什么这次问、上次不问。** 神授的整张牌面就是「哪些摸牌是强制的、
   哪些可以不摸」。他上一轮被惩罚时引擎一声不吭直接罚摸（强制），这一轮却弹了个窗口——
   两次行为不一致，而屏幕上没有任何东西解释这个不一致。玩家的第一反应是「引擎有时候忘了问」，
   于是这条**正确实现的规则会被当成 bug 报上来**。
2. **同一句话在两个来源下的最优解不一样。** 合纵②的「摸 N 弃 N」是白给的换牌机会
   （手牌数不变，通常该拿）；神授的这一问，重点在后半句「可以**不摸**」（拿了手牌就 +N，
   通常该拒）。文案把两者写成一句中性的话，等于把最关键的那半句藏起来了。

卡牌游戏里的通行做法是：**任何非常规窗口都要标出它的出处**（万智牌的堆栈每一项都写来源，
炉石的每个提示都带「因为 XX」）。玩家可以不同意你的规则，但不能不知道是谁在跟他说话。

修法见下面的 §3——不用给事件加字段，来源本来就能从快照推出来。

## 1. 五条 → 三个改动点

| 缺口 | 归到 | 为什么能合 |
|---|---|---|
| A1 结盟互换整副手牌没有反馈 | **改动 ①** | 都是「**你没动手，手牌却变了**」 |
| A5 近卫交牌的收牌方没有提示 | **改动 ①** | 同上；顺带把洗牌重分也一起盖了 |
| A2 专精的「你的色」看不见 | **改动 ②** | 两者是**同一个槽**（`Board.chosen[技能 id]`） |
| A3 吟游的当前歌声看不见 | **改动 ②** | 同上 |
| A4 神授「先问一句」没说来源 | **改动 ③** | 单独一条，一行文案 |

合并的理由不是「省事」，是**减少特例**：三个改动点里没有一个认识具体技能的名字，
所以第三批加技能时它们自动生效。

## 2. 改动 ①：手牌被外力改动时，手牌上方那行直说

### 现象

近卫的收牌方、结盟的换牌双方、洗牌的全体，手牌都会**在自己没操作的情况下**变一批。
现在唯一的提示是轮转轨下沿跑马灯里的一行小字——离手牌 30cm 远，且下一条事件就把它顶掉了。

### 落点：`lib/hud-copy.ts::handHint` + 一个新 hook

`handHint` 已经是「手牌区现在是什么情况」的**唯一解释位**（并列多选、代价牌、摸 N 弃 N、
近卫挑牌都写在这里）。外力改动只是它的又一个分支，优先级最高、几秒后自然回落：

```ts
// lib/use-hand-delta.ts —— 仿 use-bump.ts 的写法（记住上一次、变了就返回、到点自己清）
export function useHandDelta(hand: Card[]): { got: number; lost: number } | null
```

```ts
// handHint 的新首分支。`whole` = 旧手牌**一张不剩**（结盟互换 / 洗牌重分），
// 不是「既进又出」——摸完再弃、盲抽再还都会既进又出，那些不是换手牌
if (delta) return delta.whole ? "整副手牌换过了"
          : delta.lost ? `交出去 ${delta.lost} 张牌`
          : `刚进 ${delta.got} 张牌`;
```

判据落在 hook 里（`whole = lost === 上一次手牌的全部张数 && got > 0`）。
实际上「既进又出」的两条路（近卫是先摸后交、司夜②是先抽后还）**各自分在两个快照 version 里**，
所以走到 `got && lost` 同时非零的只有整副互换与洗牌重分——但判据仍按「旧手牌一张不剩」写，
不靠「它们碰巧不同时」这条运气。

### 为什么这样最省

- **不认识任何技能**：它只看「手牌 id 集合变了没有」，所以近卫、结盟、洗牌、
  以及将来任何往别人手里塞牌的技能，一条都不用加。
- **不说「为什么」，只说「发生了什么」**：原因那句已经有跑马灯与记录抽屉在讲
  （`room-log.ts` 里 `cardsHandedOver` / `handsSwapped` / `handsShuffled` 三条文案都写好了）。
  在这里再写一遍就是第二个文案源，迟早对不上。
- **入场动画一行都不用加**：`.hand .card { animation: deal }` 已经挂着，新牌进手是逐张
  发牌的观感；`<CardFace key={card.id}>` 保证换手牌那一刻整排重挂，动画自然重播。

### 测试

`lib/hud-copy.test.ts` 加三条（进牌 / 出牌 / 整副换）+ hook 自己一条「首渲染不报」。
`use-bump` 的两条约束照抄：**首渲染不闪**、**到点摘掉**。

### skipped

出牌方向的离场动画（React 卸载即消失）。等真人测试里真有人说「牌怎么没的」再加。

## 3. 改动 ②：`chosen` 徽——一个组件同时解决专精的色与吟游的歌

### 现象

专精的「你的色」和吟游的「现在唱哪支」都**只在亮出/切换那一刻的日志里出现过一次**，
之后整局都是隐性状态。这两条都是**持续改变合法性的公开信息**：专精的色决定他能不能打任意数字、
吟游的行进曲锁全场的色。卡牌游戏里这类「场上持续效果」必须常驻可见，没有例外。

### 落点：座位卡的 `.seat__tags`（已有的徽行）

```tsx
// turn-dial.tsx，紧跟 statusBadges / markBadges 之后
{chosenOf(s, p.seat) && <ChosenBadge ... />}
```

- 数据：`snapshot.chosen[技能 id] = { key, seat }`——**已经在快照里**（`index.ts:455` 整份投影，
  privacy 测试也已覆盖），引擎零改动。
- 文案规则一句话，不查技能表：**`key` 是四个颜色字母之一 → 画色点 + 颜色名，否则原样显示**。
  于是专精出「● 红」、吟游出「♪ 行进曲」，将来心火/宝藏那类「选一项」的技能自动有徽。
- 复用：色点用 `card-river.tsx` 已导出的 `colorSwatch()`，颜色名用 `lib/cards.ts::colorLabel`，
  徽壳用已有的 `.badge`——**零新 CSS**。
- 位置对：`.seat__tags` 高度固定、装不下自己横滑（`globals.css` 早就写好了），
  不会把轮转轨顶出滚动。

**封印期间必须变灰。** 01-P9 是「只压制、不清值」——被血棘封住时 `specialtyColor()` 返回
undefined（色**此刻不生效**），但 `chosen` 里那个值还留着（解封即恢复）。徽照画不变样就是在
撒谎。座位卡上已经有 `.seat--sealed` / `.skillbadge--sealed` 两个类，徽跟着挂 sealed 变体即可
——**同一条视觉规则，零新判断**（`p.statuses.includes("封印")`，turn-dial 本来就算过了）。

### 为什么不放牌桌中央

吟游的效果是全场的，按行业习惯该进中央的「持续效果区」。但**谁在唱**同样是要打的信息
（切歌要指人、封印他就停），而牌桌中央目前没有这个区。座位卡是已有的落点，先用它。
→ skipped：中央持续效果区，等第三批「诸神」的明置区一起建。

### 测试

`turn-dial.test.tsx` 四条：颜色 key 出色点、非颜色 key 原样出、`chosen` 缺席时不画
（刚亮出还没选歌 / 定不出色）、封印时挂 sealed 变体。

## 4. 改动 ③：`drawOffer` 的窗口文案带上来源

### 关键发现：来源不用引擎给

hardening spec 原本的建议是给 `drawOfferOpened` 加一个 `reason` 字段。**不需要**：
这个窗口的两个来源（合纵/连横② 与 神授）都是**受问者自己已亮出的那张技能**，
而 `snapshot.players[seat].skillId` 亮出后本来就是公开的。所以：

```ts
const by = skillById(s.players[s.drawOffer.seat].skillId)?.name;
return `${by}：可以摸 ${n} 张再弃 ${n} 张，也可以这次不摸`;
```

一处改动、零分支、零引擎改动、零新文案表——第三批再有技能开这个窗口也照样对。

> ponytail: 前提是「开窗口的技能 = 被问的人自己的技能」。哪天出现一张**替别人开这个窗口**的牌，
> 那时才给 `drawOffer` 加 `by` 字段——在那之前加就是给一个不存在的场景付钱。

### 顺带

`buttonLabel` 里 `take` / `decline` 那两条不动：按钮上写「摸 2 张再弃 2 张」/「这次不摸」
已经把两个选项讲全了，来源由上面那句话负责。

### 测试

`lib/hud-copy.test.ts`：神授持有者的 `drawOffer` 那句里出现「神授」，合纵的出现「合纵」。

## 5. 顺序与工作量

| 步 | 内容 | 触及 | 备注 |
|---|---|---|---|
| 1 | 改动 ③（文案带来源） | `hud-copy.ts` + 测试 | 最小，先做，立刻消掉一类误报 |
| 2 | 改动 ②（`chosen` 徽） | `turn-dial.tsx` + 测试 | 两条缺口一起消 |
| 3 | 改动 ①（手牌外力提示） | 新 hook + `hud-copy.ts` + `dock.tsx` 一行 | 唯一带新文件的一条 |

三步都不动 `packages/engine`，所以**引擎的 960 条测试一条都不会红**；
网页侧照旧跑 `apps/web` 的 guard rails（新事件/新 choice 缺文案会自己报警）。

做完这三步，hardening spec §3 的第 1 步即可勾掉，进入「3 人 / 4 人手动走一局」。
