## 2. 视觉方向（全新）

**代号「玄夜式盘」**——把牌桌画成一张摊平的六壬式盘：外圈天盘 = 轮转轨（刻度 + 指针 + 方向），内圈地盘 = 三堆牌河。旧稿的「深墨绿毡面 + 黄铜」整体退役。

沿用旧稿唯一一条铁律：**界面色一律去饱和，牌面五色是画面里唯一饱和的东西**——但实现方式相反：新稿的界面结构色**几乎不带色相**（玄 / 墨 / 月白三档灰蓝），只留两个语义色，牌永远最跳。

### 2.1 色（6 个命名值）

| 名 | 值 | 用途 |
|---|---|---|
| 玄 `--xuan` | `#090C11` | 桌面底色（顶部微亮的单向渐变，不用居中灯池） |
| 墨 `--mo` / `--mo-2` | `#10151D` / `#1A2330` | 面板 / 面板内凸起 |
| 月白 `--yuebai` | `#E9EEF6` | 正文（对墨 ≈ 15:1）；次级 `#8E9DB2`（≈ 6.8:1） |
| 缥 `--piao` | `#63D2C3` | **唯一的正向强调**：当前行动者、可打高亮、刻度、你的回合氛围 |
| 朱砂 `--zhu` | `#E2513C` | **只用于危险与紧迫**：惩罚链、倒计时最后 5 秒、吃下 N 张、封印 |
| 骨 `--gu` | `#F4F0E6` | 牌面骨白（牌上的字与索引块） |

牌面五色重新校准以坐稳新底色：红 `#E23B3B` / 蓝 `#3184F0` / 黄 `#F0B429` / 绿 `#31B15A`，万能牌四色 conic 不变。
旧变量名（`--brass` 等）在文件末尾保留一段别名映射，`lobby/room/encyclopedia` 三页不至于当场破相（它们的正式重画另开一轮）。

### 2.2 字（三职，全系统字体、零外链）

- **神名 / 标题**：楷体系 `"Kaiti SC", "STKaiti", "Kaiti TC", serif`——手刻感，只用在 ≥18px 的技能名与弹窗标题，字距 `0.06em`。（旧稿用宋体，此处刻意换手）
- **界面口语**：`"PingFang SC", system-ui`
- **机器量**：等宽 + `tabular-nums`，**字号放大成主角**——手牌数、堆张数、倒计时秒数、累计张数一律大号等宽，是页面上第二显眼的东西（第一是牌）

### 2.3 签名元素

**轮转轨**：一条带刻度的横轨，座位卡骑在轨上，座位之间是方向雪佛龙 `›››`，当前行动者下方一枚实心指针。它同时解决第 1、2、6 条——顺序、当前人、每个人的技能徽都在这一条上。方向反转时雪佛龙做一次 240ms 的翻转扫动（reduced-motion 下只换朝向）。

其余一切保持安静：无渐变按钮、无阴影堆叠、面板只有 1px 发丝线。

### 2.4 材质分层（2026-08-02 追加）

上面那条「保持安静」只管**界面 chrome**。牌与牌堆走相反的方向——这是卡牌品类的通行做法：
桌面越安静，牌越像实物。分层规则：

| 层 | 处理 | 令牌 |
|---|---|---|
| 桌面 | 天光渐变之上一层几乎看不见的织纹 + 四角暗角。纯平深色底会读成 PPT 而不是牌桌 | `--felt` |
| 面板 / 座位卡 / 选项 | 1px 发丝线 + **内侧**一道顶光。不加外投影 | `inset 0 1px 0 rgba(255,255,255,.04)` |
| 牌 | 唯一有厚度的东西：塑封高光、上亮下暗的色面、底缘收口、带桌面蓝的投影 | `--card-gloss` `--card-frame` `--shadow-card` |
| 牌堆 | 顶牌之下露一张歪着的底牌 + 骨白纸边的切口（层数随张数，封顶 6） | `.pile__stack::before/::after` |
| 浮层 | 影子方向跟着来向：抽屉往左打、坞上的 sheet 往上打 | `--shadow-lift` |

三条配套的**手感**规则（`--ease-tactile`）：能打的牌 hover 抬起、按下陷回；按钮按下 `translateY(1px)`；
定色四色块按下去像摁色片。全部在 `prefers-reduced-motion` 下由文件末尾那条规则一起关掉。

两处语义修正：`UNO!` 能喊时是**实心**的（描边压不住这个品类的招牌动作），喊完退成一枚安静的记号；
牌背的外框收在 `--piao-dim`，满框缥青会跟「当前行动者」抢同一个语义。

`--card-frame` 是把「骨白外框 + 色环 + 底缘收口」打成的一个整体，`--legal / --picked / --pulse`
只在它**外面**再加一圈——旧稿是整条 `box-shadow` 覆盖掉，高亮的牌反而变薄了。

### 3.2 移动（375px）

同一套结构，差异只有四条：轮转轨横向可滚（当前行动者与「你」始终保证在视口内）；三堆缩到 `--card-w: 48px` 一行放得下；堆的展开改点击；底坞含 `env(safe-area-inset-bottom)`，高度 `手牌 96px + 命令行 56px + 提示行 24px`，其余页面正常上下滚。

## 3.3 手牌排序（恒定，纯展示层）

手牌永远按同一套顺序渲染，玩家不必每回合重新找牌。**排序只发生在客户端渲染前**——引擎给的 `yourHand` 顺序不变，规则层不认识「排序」这件事。

1. **先按颜色分组**，同色相邻。颜色顺序 **红 → 蓝 → 黄 → 绿**（与定色四色块的顺序一致，两处不能各排各的）
2. **组内数字牌升序** 0 → 9
3. **该色的功能牌垫在本色组末尾**，顺序 停 → 转 → +2
4. **无色牌排在所有颜色之后**，顺序 变色 → +4 → 洗牌 → 毒

摸到的新牌按同一规则插入，不追加到末尾（否则「新牌永远在最右」和「同色相邻」互相矛盾，玩家还是要找）。多选（并列）时选中的牌**不重排**，避免手指跟着牌跑。

## 6. 对引擎 / 快照的要求（列入随后的逻辑改动）

设计稿会把这两处画出来，React 落地前需要补：

## 7. 行业与 UX 实践依据

- **计时贴着决策点**：炉石的 rope 与结束回合按钮同处、BGA 的行动条——计时器不该是一条顶栏。对应第 3 条。
- **主操作定点不动**：炉石「结束回合」、MTG Arena 的确认键位置终局不变，不可用时置灰并给理由，靠肌肉记忆而不是找按钮。对应第 5 条。
- **当前玩家 = 空间信号**：UNO! Mobile / Marvel Snap 用环与指针表达顺序与方向，而不是一行文字。对应第 1、2 条。
- **底部 sheet 不吃主内容**：Material 的 bottom sheet 规范——需要参照上下文做的选择（定色要看手牌）不能全屏遮罩。对应第 4 条。
- **渐进披露**：详情进弹窗、历史进抽屉，主屏只留「现在要做什么」。对应第 6、7 条。
- **牌堆有厚度**：实体牌桌的信息密度（还剩多少、刚打了什么）靠堆的厚度传达，数字徽记是补充不是替代。对应第 8 条。
- 质量底线：可点目标 ≥44px、`:focus-visible` 可见、`prefers-reduced-motion` 全量尊重、正文对比度 ≥4.5:1、375px 无横向溢出、零外部请求。
