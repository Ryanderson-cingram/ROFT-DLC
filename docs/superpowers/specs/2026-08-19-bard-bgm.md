# 吟游的歌声接上 BGM + 牌桌音乐开关

> 2026-08-19。四支歌声（战争序 / 樱时雨 / 活泼板 / 行进曲）各配一曲，
> 场上唱哪一支就放哪一曲；牌桌右缘加一枚图标开关，静音 / 播放。
> **零规则改动、零引擎改动、零后端改动**：要的东西快照里已经有了
> （`ClientSnapshot.chosen`，`lib/skills.ts::globalPicks`），
> 这份 spec 从头到尾只动 `apps/web` 的三个文件加一批素材。
>
> 四个产品口径已经定了（2026-08-19 与规则制定人确认）：
> ①首次进牌桌**默认静音**，点按钮才响，选择记在 localStorage；
> ②**没有歌声时放大厅曲**（先拿活泼板复制一份占位，成品后补）；
> ③吟游**被封印时暂停**，解封从原处续上；
> ④按钮是**右缘把手**，叠在「记录」上方。

## 1. 真相在哪：不用新增任何投影

歌声选中的那一支存在 `Board.chosen[skillId] = { key, seat }`（`skills/bard.ts`），
并且**已经投进快照**了：

```ts
// packages/engine/src/types.ts:520
/** 当前选中的技能分支（吟游♣5 的歌声）。当众选的，全场公开。 */
chosen?: Record<string, { key: string; seat: number }>;
```

客户端也已经有了现成的入口——牌桌上那枚歌声徽用的就是它：

```ts
// apps/web/lib/skills.ts
export const globalPicks = (s: ClientSnapshot) => allPicks(s).filter(isGlobalPick);
```

所以 BGM 是**同一份真相的第二种渲染**：牌桌上画一枚徽（`<GlobalPick>`），
音响里放一支曲。两者永远同步，因为两者读的是同一个字段。

### 1.1 认 key 白名单，不认技能 id

`Board.chosen` 那个槽**既装色也装选项名**（`lib/cards.ts:37` 的原注）——专精♥9 亮出时
往里写的是颜色码 `"R"`。两道闸门都拦得住它，两道都留着：

| 闸门 | 拦掉什么 |
|---|---|
| `globalPicks()`（`targeting: global`） | 专精的色是座位级的，本来就不在这张单子里 |
| `key in TRACKS`（四支歌的白名单） | 将来出现第二个「全场生效的选项」时不会误播 |

第二道是主要的：它让这个模块**不需要知道 `club-5` 这个 id**，
和 `<GlobalPick>` 「不认技能 id」的判据保持一致。

### 1.2 时神的永久樱时雨不响

05 的时神 ≥5 解锁的那支樱时雨是 `scope: self`、**不占场上那个全局歌声槽**
（04 §时神注 / 06-Q66），它压根不写 `Board.chosen`。所以它不触发 BGM——
这是对的：曲子放的是「全场都在吃的那支歌」，不是某人自己的减伤。

### 1.3 一次只有一支

06-Q66 已裁：全场一个槽、后唱覆盖先唱，且技能全场唯一 ⇒ `chosen` 里最多一条歌声。
代码用 `.find()` 而不是 `.map()`，多出来的（不该发生）静默取第一条，不做防御性合成。

## 2. 素材

### 2.1 落点与文件名

```
docs/music/战争序.mp3  →  apps/web/public/bgm/zhanzhengxu.mp3
docs/music/樱时雨.mp3  →  apps/web/public/bgm/yingshiyu.mp3
docs/music/活泼板.mp3  →  apps/web/public/bgm/huopoban.mp3
docs/music/行进曲.mp3  →  apps/web/public/bgm/xingjinqu.mp3
（活泼板复制一份）      →  apps/web/public/bgm/lobby.mp3
```

`apps/web/public/` 目前不存在，这次新建（Next 16 直接按路径静态服务，无需配置）。

**文件名转成 ASCII 拼音**，不是洁癖：macOS 的 APFS 存的是 NFD 分解形式，
Linux 上的构建产物与浏览器请求用的是 NFC 合成形式——中文文件名在
「本机 dev 好好的、部署上去 404」这条路上是有名的坑。反正 key→文件 的映射表
本来就要写（§1.1 的白名单），ASCII 文件名一分钱不多花。

### 2.2 体积

四支都是 192kbps / 44.1kHz 立体声，2:33 / 1:55，各 2.6–3.7MB，加占位的大厅曲共约 17MB。

- **不预加载**是硬要求（§3.2）：不开音乐的人一个字节都不该下。
- 想瘦：BGM 重编成 128kbps 大约能砍到一半，听感差别在游戏底噪里基本听不出。
  这次**不做**——先按原样上，真嫌大再压（压缩是纯素材操作，不动一行代码）。
- `lobby.mp3` 是活泼板的字节副本（+3.7MB 重复）。按你的要求保留独立文件名：
  成品到位时**只换字节不动代码**。

### 2.3 循环

`<audio loop>` 在 mp3 上有几十毫秒的缝（编码器填充，格式决定，不是 bug）。
2 分钟一循环、缝在游戏底噪里——接受。真要无缝得上 Web Audio
（`decodeAudioData` + `AudioBufferSourceNode.loop`），列在 §7。

## 3. 播放器

新文件 `apps/web/components/game/bgm.tsx`，一个组件 + 一个纯函数，约 60 行。

### 3.1 一颗 `<audio>`，不是四颗

iOS Safari 的「首次手势解锁」是**按元素**记的：哪一颗 `<audio>` 在用户手势里被
`play()` 过，之后脚本才控制得动那一颗。四颗元素 = 要解锁四次 = 改唱时必然哑一次。
一颗元素、换曲只换 `src`——解锁一次管到底，顺带也是最短的代码。

### 3.2 `preload="none"`

元素常驻，但 `src` 只在**音乐开着**时才赋值。关着音乐的人不下载任何 mp3，
开着音乐的人也只下当前这一支（大厅曲 + 场上那支歌，不是全部五支）。

### 3.3 纯函数：快照 → 该放什么

```ts
/** 四支歌声各自的曲子。key 逐字等于 `Board.chosen` 里的选项名（04 ♣5 的卡面原文）。 */
const TRACKS: Record<string, string> = {
  活泼板: "/bgm/huopoban.mp3",
  战争序: "/bgm/zhanzhengxu.mp3",
  樱时雨: "/bgm/yingshiyu.mp3",
  行进曲: "/bgm/xingjinqu.mp3",
};
/** 没有歌声时的常驻曲（无歌声是初始态，多数局全程如此）。 */
const LOBBY = "/bgm/lobby.mp3";

/**
 * 此刻该放哪一支、要不要停。**这个模块里唯一有判断的地方**，所以它是纯的、单测直打。
 * 封印（06-Q65 只压制不清值）→ 暂停而不是换曲：`src` 不变 ⇒ 解封时 play() 从原处续上，
 * 与牌桌上那枚歌声徽「退成灰但不撤」同一个口径。
 */
export function bgmFor(s: ClientSnapshot): { src: string; paused: boolean; name: string | null } {
  const pick = globalPicks(s).find((p) => p.key in TRACKS);
  if (!pick) return { src: LOBBY, paused: false, name: null };
  const sealed = !!s.players.find((p) => p.seat === pick.seat)?.statuses.includes("封印");
  return { src: TRACKS[pick.key], paused: sealed, name: pick.key };
}
```

### 3.4 副作用那一段

代码见 `apps/web/components/game/bgm.tsx`（实现即此节的定稿）。骨架：

```tsx
const [on, setOn] = useState(false);   // 首帧一律「静」：偏好读 localStorage，写进初值会 hydration 不一致
const cur = useRef("");                // a.src 读回来是绝对地址，拿它跟相对路径比永远不相等
const { src, paused, name } = bgmFor(snapshot);

useEffect(() => setOn(readPref()), []);   // readPref/writePref 各包一层 try/catch，见下

useEffect(() => {
  const a = ref.current;
  if (!a) return;
  a.volume = VOLUME;
  if (!on || paused) { a.pause(); return; }        // 关掉 / 被封印都只 pause，src 与位置留着
  const ac = new AbortController();
  const retry = () => void a.play().catch(() => {});
  void start(a, src, cur).catch(() =>
    document.addEventListener("pointerdown", retry, { once: true, signal: ac.signal }),
  );
  return () => ac.abort();
}, [on, src, paused]);

const toggle = () => {
  const a = ref.current;
  if (a && !on) void start(a, src, cur).catch(() => {});   // iOS：解锁必须在点击这一拍
  setOn(!on);
  writePref(!on);
};
```

六条**故意**：

- `play()` 的 rejection 一律吞掉。它只有两种原因（没手势 / 素材不到），
  两种都不是「出错了要告诉用户」——按钮的按下态已经把用户的意图表达完了。
- 关音乐用 `pause()` 而不是清 `src`：再打开时从原处续，且不重下。
- 开的那一下 `play()` 会被调两次（点击那一拍 + 副作用那一拍）。`play()` 幂等——
  对着正在放的元素再调一次什么也不会发生——所以**不加**「已经在放就别调」的判断：
  那是特例，不是修复。
- 补播的监听用 `AbortController` 的 `signal`，不是 `removeEventListener`：`play()` 的拒绝是
  **异步**的，可能落在组件卸载**之后**，那时候挂上去的监听没人摘得掉。已 abort 的 signal
  让 `addEventListener` 直接成为空操作，两种时序都干净（§6 有一条测试专门盯它）。
- 偏好的读写各包一层 `try/catch`：浏览器设成「拦截所有 cookie」时 `localStorage` 一碰就抛
  SecurityError，**整张牌桌不该因为一个音乐偏好白屏**。读不到当没开过，写不进只是记不住。
- `volume` 在 iOS 上是只读的（静默忽略），所以曲子本身的响度就得压住——
  桌面按 `0.35` 走，手机端听感由素材决定。**没有音量滑杆**（§7）。

### 3.5 挂在哪

`app/game/[code]/page.tsx` 里 `<LogDrawer>` 旁边一行：

```tsx
<Bgm snapshot={snapshot} />
```

它在两个 early return 之后（`missing` / `!snapshot`），所以「牌桌还没画出来」时不响，
离开这一页时随组件卸载而停。等候室与大厅**不放**音乐（这次范围只有牌桌）。

## 4. 按钮

### 4.1 位置

右缘把手，叠在「记录」上方——复用 `.drawer__handle` 的那套边缘语言，
不在页面上另开一处视觉；也不动轨与坞的既有布局（那两处的位置是设计稿定死的）。

```
   ┌──┐  ← ♪   .handle--bgm   top: calc(42% - 52px)
   └──┘
   ┌──┐
   │记│
   │录│      .drawer__handle  top: 42%
   └──┘
```

样式**先写进 `design/mockups/tokens.css`，再同步到 `apps/web/app/globals.css`**
（globals.css 头部原注：改视觉先改设计稿那边）。三行：

```css
/* 音乐开关：与「记录」同一根右缘、同一套边框，只是方的、图标居中 */
.handle--bgm { top: calc(42% - 52px); min-height: 0; width: 34px; height: 44px; padding: 0;
  display: grid; place-items: center; writing-mode: horizontal-tb; }
.handle--bgm[aria-pressed="true"] { color: var(--piao); border-color: var(--piao-dim); }
```

开着时是缥青（= 令牌里「正向 / 正在生效」的那一个色），关着时和「记录」一样的次级灰。

### 4.2 图标与可及性

内联 SVG（`currentColor`，18px），开着画音箱 + 声波，关着画音箱 + 叉：

```tsx
<button type="button" className="drawer__handle handle--bgm" aria-pressed={on}
  aria-label={on ? `关掉背景音乐（正在放：${name ?? "大厅曲"}）` : "打开背景音乐"}
  onClick={toggle}>
  <svg viewBox="0 0 24 24" width="18" height="18" aria-hidden="true"
       fill="none" stroke="currentColor" strokeWidth="1.6" strokeLinecap="round">
    <path d="M4 9.5h3.2L11.5 6v12L7.2 14.5H4z" />
    {on ? <path d="M14.8 9.2a4 4 0 0 1 0 5.6" /> : <path d="M15 9.5l5 5m0-5l-5 5" />}
  </svg>
</button>
```

- 状态走 `aria-pressed`，不是把状态塞进可及名（切换按钮的标准形状）。
- 曲名进 `aria-label`：读屏用户听得到「现在放的是战争序」，
  而**改唱本身不额外播报**——行动记录里已经有「××：改唱「战争序」」那一条，
  播两遍是噪音。
- 图标 `aria-hidden`：名字由 `aria-label` 给（同 `.drawer__close` 的做法）。

## 5. 状态机

| 事件 | 快照上的变化 | 音乐 |
|---|---|---|
| 进牌桌（首次） | — | 静音（默认关），按钮暗 |
| 点开按钮 | — | 大厅曲起播，偏好写 `on` |
| 吟游选歌 | `chosen["club-5"] = { key: "战争序" }` | 换成战争序，从头放 |
| 改唱 | 同上，`key` 变 | 换曲，从头放（硬切，§7） |
| 吟游被封印 | 该座位 `statuses` 含「封印」 | `pause()`，位置留着 |
| 解封 | 状态消失 | 从原处续上 |
| 吟游出局 / 技能失效 | `chosen` 是否还在由引擎决定 | 跟着 `chosen` 走，本模块不判 |
| 再来一局 | 路由回等候室 → 组件卸载 | 停；重进牌桌按偏好自动续（被挡则等第一次点击） |
| 关掉按钮 | — | `pause()`，偏好写 `off` |
| 终局弹窗 | `phase = "finished"` | **不特判**，照旧放着（§7） |

## 6. 测试

`apps/web/components/game/bgm.test.tsx`，**40 条**，两层，跟仓库现有分工一致
（纯函数打真值，组件那层只钉结构、属性与副作用的调用）。

**`bgmFor()`——纯，14 条**

| 场景 | 钉住的事 |
|---|---|
| 没有 `chosen` / `chosen` 是空对象 | 大厅曲、不暂停、`name` 为 null |
| 四支歌各一条（`it.each`） | 各自的文件与 `name` |
| 四个文件互不相同、都在 `/bgm/` 下 | 表本身没有重复项与错路径 |
| 改唱 | 换曲（06-Q66 一个槽） |
| **唱歌的人**被封印 | `paused`，且 `src` **不变**（不回落大厅曲） |
| 被封印的是**别人** | 照唱 |
| 专精♥9 的定色（key 是颜色码） | 大厅曲——那个槽既装色也装选项名 |
| 认不出的 key（`安魂曲`） | 大厅曲——**第一道闸**：它压根不是哪条子效果 |
| 吟游①自己（`club-5` 的 key `"1"`）、强袭♦1② | 大厅曲——**第二道闸**：这两条真的是 `targeting: global`，第一道闸放行，只有 `TRACKS` 白名单拦得住（拦不住就是 `src: undefined`） |
| 歌声与专精的色并存 | 放歌声 |
| `seat` 指向不在场的座位 | 不炸，退成「不暂停」 |

**`<Bgm />`——jsdom，26 条**

| 场景 | 钉住的事 |
|---|---|
| 首次进牌桌 | 不出声、不设 `src`、`aria-pressed="false"` |
| `<audio>` 的属性 | `loop` + `preload="none"`（关着音乐一个字节都不下） |
| 点开 / 再点关 | play / pause、`localStorage` 跟着写、按下态跟着变 |
| 关掉再打开 | **不重设 `src`**（重设 = 从头放），play 共 4 次（每次「开」两拍，幂等） |
| 上次开着 / 上次关着 | 进牌桌自动接上 / 仍然是静的 |
| 唱起歌声、改唱 | 换 `src`，曲名进可及名 |
| 快照变了但该放的没变 | **不重设 `src`、不重复 play**（不然每收一条快照就从头放） |
| 唱歌的人被封印 → 解封 | pause → play，全程 `src` 不动（原处续上） |
| 歌声没了 | 回大厅曲 |
| 音乐关着时唱歌 | 什么都不做，连 `src` 都不设 |
| 封印期间打开音乐 | 按钮是开的，声音仍然停着 |
| 自动播放被挡 | 第一次 `pointerdown` 补播；补播只挂一次 |
| **卸载后再点页面** | 不补播（这条在换成 `AbortController` 之前是**红的**——它逮住了一个真实的监听泄漏） |
| `play()` 被拒 | 不弹错、不改按钮状态 |
| 音量 / 图标 / 类名 | `0.35`、`svg[aria-hidden]`、复用 `.drawer__handle` |
| **服务端渲染的首帧** | `aria-pressed="false"` 且没有 `src`——偏好写进 `useState` 初值就会 hydration 不一致（用 `renderToStaticMarkup` 钉） |
| StrictMode 挂两次 | 副作用幂等，不出事 |
| **`localStorage` 被锁死**（浏览器「拦截所有 cookie」时一碰就抛） | 不白屏、音乐照开，只是记不住 |

jsdom 没实现 `HTMLMediaElement` 的 play/pause（调用会抛 Not implemented），所以这一层先接管
三个口子——`play` / `pause` / `src` 的 setter：

```ts
play = vi.spyOn(HTMLMediaElement.prototype, "play").mockResolvedValue(undefined);
pause = vi.spyOn(HTMLMediaElement.prototype, "pause").mockImplementation(() => {});
setSrc = vi.spyOn(HTMLMediaElement.prototype, "src", "set");   // 不 mock 实现：只数次数，值照旧落到属性上
```

`src` 的 setter 是那几条「续播 / 不重头放」断言的**唯一**着力点：从元素上读 `src`
看不出「有没有被重新赋过值」，而重新赋值正是「从头放」的成因。

真实的「有没有声音」jsdom 判不了——那一条靠手测（清单在 §8）。
`test-support/render-game.tsx` 不含 `<LogDrawer>` 与 `<Bgm>`，现有测试一条都不受影响
（全仓 498 条绿）。

## 7. 这次不做（各自的升级路径）

| 不做 | 什么时候做 |
|---|---|
| 音量滑杆 | 固定 0.35。有人说「太吵/太小」再加——那时它是一个 `<input type=range>` + 一个 localStorage 键 |
| 改唱时淡入淡出 | 现在是硬切。嫌突兀就加一段 300ms 的音量斜坡（一个 `setInterval`，约 10 行），或上 Web Audio 的 `GainNode` |
| 无缝循环 | mp3 的填充缝。真要无缝：`decodeAudioData` + `AudioBufferSourceNode.loop`（整套换成 Web Audio） |
| 终局切回大厅曲 | 一行分支：`if (s.phase === "finished") return { src: LOBBY, ... }`。要不要看手感 |
| 出牌 / 摸牌 / 惩罚的音效 | 另一件事：SFX 是事件驱动（要读 `room-log` 的事件流），不是状态驱动 |
| 等候室 / 大厅 / 百科页的 BGM | 这次只有牌桌。要铺开就把 `<Bgm>` 提到 `app/layout.tsx`，代价是它得自己知道「现在没有牌桌」 |
| mp3 搬去 Supabase Storage / CDN | 17MB 直接进仓。仓库嫌胖了再搬（换的是 `TRACKS` 里的五个字符串） |
| 服务端参与 | 一个字节都不需要：曲子是快照的纯函数，四个人各自的音量与开关互不相干 |
