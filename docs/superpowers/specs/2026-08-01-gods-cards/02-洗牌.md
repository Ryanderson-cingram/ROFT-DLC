# 洗牌（shuffle，3 张）——三选一并定色

先读 `README.md`。规则出处：**KB 05 §2b「洗牌（3 张）」+ 四条 2026-07-31 裁定**、03 §6（选项①的定义）、01-U5/U5b、01-G5（选项③照抄的对象）、06-Q55（三堆模型）。

> ⚠️ **命名冲突**：卡面的「洗牌」= 打乱并重分**所有玩家的手牌**（本 spec）；与「摸牌堆见底时把牌河洗回摸牌堆」（01-U8，`draw.ts::drawCards` 里那段）是两回事。代码里前者叫 `shuffleCard` / `redistribute`，后者叫 `reshuffle`，**不要混用命名**。

## 一句话

无色功能牌。打出时**三选一并定色**：① 合并打乱全体手牌重新分发 ② 摸一弃一 ③ 取消别人正在进行的①。

## 0. 动作契约

`Action.playCards` 增加一个提交前的客户端选择：

```ts
/**
 * 洗牌牌的三选一（05 §2b）。与 `chosenColor` 同性质——提交前的客户端模态，
 * 不是服务端窗口，所以不进 legalActions（同「无色牌不带 chosenColor」那条注释）。
 * 选项③是**响应**，只能从 shuffleCancel 窗口打出，不能走 playCards。
 */
shuffleChoice?: "shuffle" | "drawDiscard";
```

`Action.respond` 增加：

```ts
/** 洗牌·选项③ 的取消牌同样要定色（卡面「三选一并决定颜色」）。同 playCards 的 chosenColor。 */
chosenColor?: Color;
```

拒因：打洗牌不带 `shuffleChoice` → `shuffle_choice_required`；带了但不是那两个值之一 → `bad_shuffle_choice`；非洗牌牌带了 `shuffleChoice` → `shuffle_choice_not_allowed`。`malformed()` 里给 `respond.chosenColor` 补一条值域校验（复用既有的 `COLORS.includes`）。

## 1. 中间态与窗口

```ts
/**
 * 洗牌牌两个窗口的上下文。挂在**牌桌**上而不是 PendingWindow 上：
 * `drawnId` 是暗信息（刚摸到哪张只有自己知道），而 PendingWindow 整个进快照——
 * 写进去就等于当众念出来了（同 `PendingSwap` 的理由）。
 */
export interface ShufflePending {
  /** 打出洗牌的那个人 */
  seat: number;
  /** 打出时选的那一项。摸到牌之后就用不上了，选项②开窗口时不再带。 */
  choice?: ShuffleChoice;
  /** 选项②：刚摸那张牌的 id，超时默认弃它。选项①不带。 */
  drawnId?: string;
  /**
   * 与这次出牌同时喊的 UNO（U6）。选项②必须透传：摸 1 会把手牌顶离 1 张，`commit` 的
   * `syncUno` 当场把已喊清掉，等弃完回到 1 张时已喊就没了——而打出者在窗口期拿不到
   * `callUno`（那时他手上 2 张），窗口一关必被抓。同 `ParallelPending.declared.sayUno`。
   */
  sayUno?: boolean;
}
```

`Board` 加 `shufflePending?: ShufflePending`（同 `playPending` / `swap` 的写法：窗口挂着时才有，结算即删）。

| 窗口 type | actors | defaultChoice | 语义 |
|---|---|---|---|
| `shuffleDiscard` | `[打出者]` | `"drawn"`（**哨兵**，不是牌 id——牌 id 是暗信息，见 `swapReturn` 的同款注释） | 单人；从**全部手牌**里挑一张弃进弃牌堆 |
| `shuffleCancel` | 其他座位中**手上有洗牌牌**的 | `"pass"` | **先到先得**，一人取消即关（照抄 `interrupt`） |

两个窗口的 `resume` 都是 `"turnStart"`；`deadline` 30 秒（复用既有的 `WINDOW_MS`）。
`respond` 与 `claimTimeout` 的 dispatch 各加一个分支。

## 2. 选项① 洗牌（合并重分）

- **先探测取消者**：其他座位中手上有 `face === "shuffle"` 牌的人。有 → 开 `shuffleCancel` 窗口，牌桌上挂 `shufflePending: { seat }`，**先不重分**。没有 → 直接重分。
- **重分算法**（03 §6 + 05 §2b）：
  1. 合并全体手牌——按**座位序**拼接（确定性），得 `pool`
  2. `shuffle(pool, ctx.rng)`（复用 `deck.ts::shuffle`）
  3. 从 `nextSeat(board, 打出者)` 开始、按 `direction` 逐张轮流发，直到发完。人数除不尽时靠前的人多一张——**这是轮流发牌的自然结果，不要写取整公式**。
- **`saidUno` 全部清零**：每个人拿到的都是一手全新的牌，U6 的「手牌数离开 1 张后已喊状态作废」在合并的那一刻就成立了（合并时人人手牌为 0）。`commit` 的 `syncUno` 只会**清**不会**补**，所以这一步要显式做。清完之后手上恰好 1 张的人须喊 UNO、他人可抓（U6/U7 的既有机制自动生效，**不用写新代码**）。
- **U5b**：重分后有人手牌为 0 → **不判胜**（收官早在末牌离手时判过了，见 §4）。打出者若为 0，走 §4 的 `settleEmptyHand` 补摸 1 → 手牌 1 → 须喊 UNO。
- **交回合**：`passTurn(board, 打出者)` → 打出者的下家（重分的起点也是他，两者同一个人，纯属巧合，各写各的）。

### 事件

```
{ type: "handsShuffled", public: { seat: 打出者, counts: [每座位新手牌数] },
  audit: { order: [打乱后的全部牌 id], deal: [[座位0 拿到的 id...], ...] } }
```

**牌序与谁拿到哪张绝不进 `public`**（README §5 的隐私三分）。手牌**张数**是公开的（快照本来就有 `handCount`），所以 `counts` 进 public 没问题。

> **2026-08-01 复查后定稿**：本来还打算对每个座位各发一条 `handReplaced`（private 带新手牌）。
> 已删除——重放需要的完整发牌在 `audit.deal` 里就有，而 `private_payload` 有列级 grant
> （`supabase/migrations/0001_init.sql:90`），客户端根本读不到；手牌本身走快照的 `yourHand`。
> 那 N 条事件不携带任何新信息。**这与 `cardsDrawn.private` 不同**：那一条是「谁摸到了哪几张」的
> 唯一记录，没有 audit 兜底，所以必须留着。

## 3. 选项② 摸一弃一

1. `drawCards(board, { kind: "rule", base: 1, seat }, ctx.rng)` + `giveTo`（同毒：牌面效果，非惩罚非技能 → `kind: "rule"`）。发 `drawEvents`。
2. 摸到 0 张（牌堆枯竭）→ **不开窗口，不弃牌**（03 §2「摸到手里的牌数量不能少于弃牌数量」），直接进 §4 收尾。
3. 摸到 1 张 → 开 `shuffleDiscard` 窗口，挂 `shufflePending: { seat, drawnId: 那张牌的 id }`。
4. `respond { choice: <手牌里任意一张的 id> }` → 该牌进**弃牌堆**（`discardPile`，不是出牌堆；06-Q55 三堆模型，弃牌不改牌顶也不改跟色）→ 进 §4 收尾。
   - 校验：`choice` 必须是**当前手牌**里的 id，否则 `not_in_hand`。
5. 超时 / `claimTimeout` → `defaultChoice: "drawn"` 哨兵 → 弃 `shufflePending.drawnId` 那张。
6. 事件：`{ type: "cardsDiscarded", public: { seat, cards: [那张] } }`（弃牌堆全公开，02 §5——既有事件类型，直接复用）。

## 4. 通用收尾（三个选项 + 取消 共用）

**这一段就是 README §1 要从 `settlePlay` 开头挪下来的那块。抽成一个函数，四条路径共用：**

```
settleWin(board, seat, card)        ← 判在牌面效果**之前**（01-U5c，2026-08-01）
  手牌 = 0 且（数字牌 or 司夜③ 盗够本）→ 判胜终局，牌面效果不再结算

settleEmptyHand(board, seat, ctx)   ← 判在牌面效果**之后**（01-U5）
  手牌仍为 0 → 补摸 1 张（drawCards { kind: "rule", base: 1 }，不是惩罚）
```

**两个判定时点不同，是两条独立的规则。** `settleWin` 在 `settlePlay` 的入口跑：末牌打出的那一刻
就定胜负，所以持够 5 盗的司夜拿洗牌收官时，三选一整个不结算、取消窗口也不会开——**取消夺不走
已经到手的胜利**（原 06-Q59/Q61，2026-08-01 裁定：「打出后无论选择什么都算胜利并结束」）。

`settleEmptyHand` 的调用点：毒之后、洗牌①重分之后、洗牌②弃牌之后、取消结算里（被取消者 +
取消者各一次）。取消者那一次前面还要再跑一次 `settleWin`——他确实打出了末牌，与从 `playCards`
打出同一口径。

## 5. 选项③ 取消（`shuffleCancel` 窗口）

**完全照抄劫营 01-G5**（05 §2b 洗-3）。`raid.ts::settleRaid` 是最近的抄写对象。

- `respond { choice: "cancel", cardIds: [自己的一张洗牌牌], chosenColor }`：
  - 校验：牌在手上、`face === "shuffle"`，否则 `not_in_hand` / `bad_choice`；缺 `chosenColor` → `color_required`。
  - 结算顺序（**顺序有意义，别调**）：
    1. 取消牌离手 → 压 `playedPile[0]`；`activeColor = chosenColor`、`activeFace = null`、`drawnPlayable = null`
    2. **不重分**（选项①的效果整个作废）
    3. 被取消者（`shufflePending.seat`）跑 `settleEmptyHand`——他若把洗牌当末牌打出，此刻手牌为 0 → 补摸 1。**收官在这里不可能发生**：持够盗的司夜早在出牌那一刻就赢了、窗口根本不会开
    4. 取消者先跑 `settleWin`（他确实打出了末牌，5 盗照样赢），没赢再跑 `settleEmptyHand` 补摸 1
    5. `passTurn(board, 取消者)` → **取消者的下家**继续出牌（取消者本人不进入自己的回合）
  - 清 `shufflePending`。
- `respond { choice: "pass" }` / 超时 / 全员放弃 → **执行重分**（§2），然后照 §2 收尾交回合。
- **不可连锁**（洗-4）：取消牌的落地**不再开** `shuffleCancel` 窗口——只有走 `playCards` 且 `shuffleChoice === "shuffle"` 的那一次才开。
- 取消者付出的就是普通的一张牌，不摸补偿、不占 V7 额度、不发 `skillActivated`（这是牌面不是技能）。

### 事件

`{ type: "shuffleCancelled", public: { by: 取消者, target: 被取消者, card: 取消牌, color: chosenColor } }`

## 6. Worked examples

**A. 选项①，无人可取消**
4 人 A→B→C→D，手牌数 3/4/2/5（共 14 张），A 打出洗牌选①定蓝，其余三人手上都没有洗牌牌。
→ A 手牌剩 2，合并 2+4+2+5 = 13 张打乱；从 **B** 开始轮流发：B/C/D/A 各拿 4/3/3/3。
→ 跟色蓝、牌顶是洗牌、`saidUno` 全清、轮到 B、`version` 恰好 +1（没开窗口）。

**B. 选项①，被取消**
同上但 C 手里有一张洗牌。A 打出洗牌选①定蓝 → 窗口开（actors=[C]）。
C `respond { choice: "cancel", cardIds: [C 的洗牌], chosenColor: "Y" }`。
→ 不重分，全体手牌一张没动；牌顶 = C 的洗牌、跟色**黄**；C 手牌 −1；**轮到 D**（C 的下家）——B 这一轮被跳过，是 G5 的固有后果。

**C. 选项②作末牌**（A 没有司夜，或盗不够 5）
A 手里只剩 1 张洗牌，打出选②定红 → `settleWin` 收不了官 → 手牌 0 → 摸 1（手牌 1）→ 窗口开
→ A 弃掉那张（手牌 0）→ `settleEmptyHand` 补摸 1 → 手牌 1 → **A 须喊 UNO**，B/C/D 可抓。轮到 B。

**D. U5b 重分得 0 张**（规则制定人原话的场景）
4 人各剩 1 张，只有 A 手里那张是洗牌。A 打出洗牌选①定红 → A 手牌 0，合并 B/C/D 的 3 张
→ 从 B 开始发：B/C/D 各 1 张，A **分到 0 张**。
→ **不判胜**（`settleWin` 在出牌那一刻已判过，A 收不了官），`settleEmptyHand` 补摸 1
→ A 手牌 1 → **A 须喊 UNO**，他人可抓。轮到 B。

**E. 司夜③ 以洗牌收官**（01-U5c，2026-08-01）
A 持司夜、已亮出、有 5 枚盗，手里只剩 1 张洗牌。A 打出它，三选一随便选哪个都行。
→ `settleWin` 在牌面效果之前命中：扣 5 盗、**当场终局 A 获胜**。
→ 重分不发生、弃牌窗口不开、取消窗口也不开——**别人夺不走**。毒作末牌同理（那 3 张不再摸）。

## 8. 测试清单（最低）

1. Worked example A/B/C/D 逐条全断言（手牌数、跟色、牌顶、轮到谁、`version` 增量）。
2. **牌不增不减**：重分前后 `allCards` 的多重集合完全相等（id 不重不漏）。
3. 重分的发牌起点是**打出者的下家**，且随 `direction: -1` 反向。
4. 除不尽时靠前的人多一张（13 张 4 人 → 4/3/3/3，起点先拿）。
5. `saidUno` 重分后全清；恰好 1 张的人 `legalActions` 里有 `callUno`，他人有 `catchUno`。
6. 隐私：`projectView(其他座位)` 里搜不到打出者的新手牌；`handsShuffled` 的 `public` 里没有任何牌 id；牌序只在 `audit`。
7. 选项②：正常摸 1 弃 1（手牌数不变、弃牌进 `discardPile` 不进 `playedPile`、牌顶与跟色不变）；弃非手牌 id → `not_in_hand`；超时弃刚摸那张。
8. 选项②牌堆枯竭摸到 0 张 → 不开窗口、不弃牌、引擎不抛。
9. 取消：Worked example B 全断言；`chosenColor` 缺失 → `color_required`；拿非洗牌牌取消 → `bad_choice`；非 actor 响应 → `not_your_window`。
10. **不可连锁**：取消牌落地后 `state.pendingWindow` 为 undefined（没有第二个 `shuffleCancel`）。
11. 取消窗口只在选项①开：选项②、选项③落地都不开；场上没有别人持洗牌牌时选项①也不开（`version` 恰 +1）。
12. 取消后被取消者手牌为 0 → 补摸 1、不判胜；取消牌是取消者最后一张且盗不够 → 补摸 1、不判胜。
16. **01-U5c**：司夜持 5 盗以洗牌收官 → 打出即胜、三选一不结算、取消窗口不开（worked example E）；毒同理；盗只有 4 枚 → 收不了官，走 U5b 那条路。
17. **U6**：选项②带 `sayUno` 打出 → 弃完之后已喊仍成立、不可被抓；没带 → 弃完可被抓。
13. `shuffle_choice_required` / `bad_shuffle_choice` / `shuffle_choice_not_allowed` 三条拒因。
14. 窗口期间 `callUno` / `catchUno` 仍可用（uno 动作不被窗口挡的既有行为回归）。
15. 基础包里没有洗牌牌（`buildDeck("base")` 回归断言）。
