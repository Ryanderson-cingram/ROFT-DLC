## 0. 本批要做的事

诸神包（`rulePack: "gods"`）比基础包多出 8 张牌：**毒 5 张 + 洗牌 3 张**。牌早就在
`deck.ts::buildDeck` 里发出去了，但引擎**没有任何行为**——打出去只当普通变色牌结算。
大厅因此把诸神包整个禁用了（`apps/web/app/lobby-forms.tsx`）。本批补上这两张牌的效果。

卡面与全部裁定：**KB 05 §2b**。两张牌都是**无色牌**（`color === null`，打出时必须带 `chosenColor`）。

| 牌 | 张数 | 效果 |
|---|---|---|
| 毒 | 5 | 打出时**打出者自己**摸 3 张并定色 |
| 洗牌 | 3 | 三选一并定色：① 合并重分全体手牌 ② 摸一弃一 ③ 取消一次其他玩家的洗牌 |

## 1. 本批的共享前提：U5 判定时点改了

**这是本批唯一一处会碰到既有行为的改动，两份 spec 都依赖它，谁先动谁做。**

01-U5 原文「功能牌打出后手牌若归零，须再摸 1 张」的**判定时点**在 2026-07-31 被规则制定人
澄清为：**这张牌自身的效果全部结算完、准备交回合的那一刻**，而不是「牌一离手」。

- 现状：`play-cards.ts::settlePlay` 在函数**开头**就判 `played.hands[seat].length === 0`，
  补摸 1 张，然后才跑获盗/惩罚链/交回合。
- 要求：这一段挪到**牌面自身效果之后**。
- **回归保证**：+2 / +4 / 停 / 转 / 变色 自身都不给打出者加牌，判定时点前后同解 → 既有测试
  一条都不该改。**如果你发现必须改既有测试，说明挪错了位置，停下来回报。**
- 差别只出现在毒（摸 3 → 不补摸）与洗牌（① 重分后可能非 0；② 摸一弃一后仍是 0 → 补摸）。

司夜♣3③「持够盗则末牌放宽」的收官判定同样跟着挪：它问的也是「手牌空了没有」，
所以毒/洗牌把手牌填回去之后就不再触发。这是裁定的自然推论，不是新规则。

## 3. 新窗口一览（两份 spec 各自建自己的）

既有窗口语义两种范本：`punishStack`（先到先得，一人响应即关）、`skillDraft`（收集全员）。
本批新增的两个都是**先到先得**那一支，`interrupt`（劫营）是最近的抄写对象。

| 窗口 type | 谁开 | actors | defaultChoice | 语义 |
|---|---|---|---|---|
| `shuffleDiscard` | 洗牌·选项② | 打出者自己（单人） | 刚摸那张牌的 id | 从全部手牌里挑一张弃掉 |
| `shuffleCancel` | 洗牌·选项① | 其他玩家中手上有洗牌牌的 | `pass` | 先到先得，一人取消即关 |

两个窗口都要在 `punish.ts::respond` 与 `punish.ts::claimTimeout` 的 dispatch 里加分支，
并在 `index.ts::legalActions` 里给出可点动作（**客户端零规则**：UI 只渲染 legalActions）。

## 4. 出牌路径的接入点

单张出牌的结算在 `play-cards.ts::settlePlay`。它已经被劫营♦10 的窗口切成两段
（`resolvePlay` 摆牌 → 可能开 `interrupt` 窗口 → `settleRaid` pass 后回到 `settlePlay`），
**毒与洗牌的效果都排在 `settlePlay` 内、U5 补摸之前**。顺序：

```
resolvePlay: 牌离手、压牌顶、定色、（可能开劫营窗口）
settlePlay:
  1. 牌面自身效果  ← 毒摸 3 / 洗牌三选一（选项①可能开 shuffleCancel、选项②开 shuffleDiscard）
  2. 司夜③ 收官判定（手牌仍为 0 且盗够 → 判胜）
  3. U5 补摸（手牌仍为 0 且非数字牌 → 摸 1）
  4. 数字牌收官判胜
  5. 获盗 / 惩罚链 / 交回合
```

开了窗口的分支要把「窗口关掉之后从第几步接着跑」记进牌桌上的中间态字段
（同 `playPending` / `parallelPending` 的做法），**不要**把闭包塞进 `PendingWindow`——
`GameState` 要存库、要重放，里面只能有可序列化的数据。
