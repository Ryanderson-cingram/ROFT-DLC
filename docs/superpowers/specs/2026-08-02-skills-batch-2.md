## 1. 为什么是这十个

首批把**摸牌数结算层级**（02 §7 的 L0–L6）整台机器建起来了，但只有 L2/L4/L5 有人用：
**L1 与 L6 至今空跑**——`resolveDrawCount` 把 `procedures` 算出来了，`drawCards` 里没有任何
调用方消费它。这一批的主题就是**把已经建好的机器接上电**，而不是再造机器。

选取口径：04 里标 ✅（规则已拍板）且尚未实现的共 14 个，去掉四个要新地基的，取十个。

| # | 技能 | 复用 | 新增 | 档 |
|---|---|---|---|---|
| 1 | ♥10 伤逝 | `drawModifier` **L1** | 注册 `replacement` kind | 数据 |
| 2 | ♥8 异议 | `marks`（异）+ `response` + `turn_flow` | — | 数据 |
| 3 | ♠J 忍戒 | `drawModifier` **L6** 的类型层 | **L6 执行面** + `draw_procedure` | 机制 |
| 4 | ♠8 八门 | L6 执行面（同上） | — | 数据 |
| 5 | ♠5 合纵 | `drawDiscard(N)` 窗口 | ↓ | 机制 |
| 6 | ♠6 连横 | 同上（与合纵对称） | — | 数据 |
| 7 | ♥6 近卫 | `response` + `PunishChain.segments` | 交牌 handler | 小 |
| 8 | ♥5 神授 | — | `draw_obligation` | 小 |
| 9 | ♣5 吟游 | L2/L3/L4 + `color_rule` | 歌声槽 + L2/L3 作用域 | 机制 |
| 10 | ♥9 专精 | `statuses` / `play_legality` / `color_rule` | 颜色槽 | 钩子多 |

**明确不做**（留给第三批「诸神」）：伪神♣6 / 万变♣8 / 飞升♣K 要 G1 神化连出或明置扣置区，
Board 里两者都不存在（`ascensions` 至今硬编码 0）；先哲♠2 要「强制发动他人技能」，
是跨座位代理执行的新控制流。

## 3. 新增的机制（六件，按被复用次数排序）

### 3.1 `drawDiscard(N)` —— 一个窗口摸 N 弃 N

**三个技能共用，是这一批杠杆最高的一件。**

03 §2（2026-08-02）：一次摸满 N 张、再从**摸完之后的整副手牌**里挑 N 张弃掉，
**不是 N 个「摸 1 弃 1」**；中途没有可观察的中间态。

**做法是泛化而不是新建**：`shuffle-card.ts` 的 `shuffleDiscard` 窗口已经是 N=1 的实现。
把它抽到 `actions/draw-discard.ts`：

```
openDrawDiscard(state, b, seat, n, resume, ctx) → 摸 n 张（走 drawCards，吃全部层级修正）
                                                  → 挂 { type: "drawDiscard", picks: n } 窗口
settleDrawDiscard(state, action, ctx)           → 校验 cardIds 长度 === n 且都在手上 → 弃掉 → resume
```

- 弃的牌进**弃牌堆**（06-Q55），不是出牌堆
- 超时默认：弃**刚摸到的那 n 张**（沿用 `shuffleDiscard` 的 `DISCARD_DRAWN` 哨兵思路；
  ⚠️ 哨兵不能写真牌 id，`PendingWindow` 整个进快照）
- 摸不够 n 张（牌堆枯竭）→ 按实际摸到的张数弃，不足即不弃（03 §2「摸到的不能少于弃的」）
- `shuffleDiscard` 改成调用它，`SHUFFLE_CHOICES` 的「摸一弃一」不再有自己的窗口类型

### 3.2 L6 后置程序的执行面

类型层（`DrawProcedure`）已经有了，`resolveDrawCount` 也已经在返回 `procedures`——
**缺的是消费者**。`drawCards` 现在把 `resolution.procedures` 丢掉了。

```
drawCards(...) → { board, drawn, resolution }
                 调用方按 resolution.procedures 决定还要做什么
```

第一个程序：**忍戒**「按最终值 N 多摸 min(N,6) 张再弃等量」。它落在惩罚结算之后，
所以由 `punish.ts` 的吃牌路径消费——多摸走 `drawCards`（`kind: "skill"`，不是 punish：
那多摸的不是惩罚），弃走 §3.1 的窗口。

同时把 `draw_procedure` 加进 `primitives`（现在不在集合里，忍戒会落进 `unsupported`）。

### 3.3 `replacement` kind（L1）

伤逝的围栏块已经写着 `kind: replacement` + `layer: [L1]`，但 `replacement` 不在 `primitives`
集合里、`structured` 也没置 true，所以它至今不进池。

要做的只有三件：注册 kind、置 `structured: true`、在 `draw-passives.ts` 里产出那条 L1 修正
（值 = 按**链上 +2/+4 的张数**掷骰之和，掷骰走已有的 `dice` 原语，在组装修正**之前**算完——
`resolveDrawCount` 是纯函数，随机不能进去）。

⚠️ 张数 ≠ 贡献总和：`PunishChain.segments.length` 才是「链上几张」，`total` 是加总后的贡献。
01-P13 明写伤逝**忽略贡献总和**。

### 3.4 歌声槽

**全场一个槽，不是逐座位字段**（06-Q62 全场生效 + 06-Q66 技能唯一 ⇒ 只可能有一支在唱）。

```ts
/** 01-S20 / 04 ♣5。缺席 = 无歌声（亮出时的初始态）。 */
song?: { name: "战争序" | "樱时雨" | "活泼板" | "行进曲"; seat: number };
```

- `seat` 是唱的人——被封印时按压制层关掉效果，**值留着**（06-Q65：解封回到原来那一支）
- 切换占主动条（01-S20），开唱条件是「上家这一轮打出的不是 +2/+4」
- 时神的永久樱时雨**不占这个槽**（`scope: self`，与场上歌声并存）

### 3.5 L2/L3 的作用域

`DrawModifier` 现在只有 L4 带 `scope: "self" | "global"`。06-Q62 裁定歌声**全场生效**，
所以 L2（活泼板）与 L3（战争序）也要有作用域：

```ts
| { layer: "L2"; source: string; scope: Scope; delta: number }
| { layer: "L3"; source: string; scope: Scope; factor: number }
```

`drawModifiersFor` 的采集口径从「按摸牌者收自己的修正」扩成「自己的 + 全场的」。
层序**不变**——06-Q62 原话「×2 是惩罚最后计算的，即先计算加减」与现有 L2→L3 逐字一致。

### 3.6 两个小钩子

- **`draw_obligation`**（神授♥5）：改 U1「无牌可出必须摸牌」的强制性。01-S17：仅列情形才
  一定要摸，否则**可以不摸直接结束**；相对恋战**神授优先**。落点是 `legalActions` 里
  `drawCard` / `endTurn` 的给法，不碰摸牌数
- **颜色槽**（专精♥9）：per-seat 的一个 `Color`，亮出时定死。四个钩子各自很小——
  该色 +2 无效（惩罚链）/ 当前色为你的色时可打任意数字（`play_legality`）/
  变色只能选你的色（`color_rule`）/ 免疫五彩（`statuses`）

## 4. 实施顺序

每一步都能单独合并、单独回滚。**先建被复用的，再接消费它的**。

| 步 | 内容 | 完成信号 |
|---|---|---|
| 1 ✅ | `replacement` kind + 伤逝 | 伤逝进池，`skills.pool.length === 11` |
| 2 ✅ | 异议（`marks` 的「异」+ L2 + 响应窗口） | 12 |
| 3 ✅ | `drawDiscard(N)` 泛化；`shuffleDiscard` 改为调用它 | 洗牌②的既有行为断言一条不改仍绿 |
| 4 ✅ | L6 执行面 + `draw_procedure` + 忍戒 | 13 |
| 5 ✅ | 八门（吃 §3.1 + §3.2 + 五彩的执行面） | 14 |
| 6 ✅ | 合纵 / 连横（①结盟换牌 + ②无相应的摸弃） | 16 |
| 7 ✅ | 近卫（**第二支 L6 后置程序** + 交牌给链首，01-P12） | 17 |
| 8 ✅ | 神授 + `draw_obligation` | 18 |
| 9 ✅ | 吟游四支歌声（`option_of` 选项分支 + 全场作用域） | 19 |
| 10 ✅ | 专精四个钩子 | 20 |

第 3 步是分水岭：它之前都是「数据 + 注册」，之后才动窗口机制。

**第 1–2 步的落地记录（2026-08-02）**，两处与本文原计划不同，照实记：

- 伤逝的 L1 与异议②的 L2 **都不由 `drawModifiersFor` 产**。它是纯函数，既拿不到 rng
  （伤逝要掷骰），也不知道玩家这次实弃了几枚异——两者都由调用方算好走 `drawCards`
  的 `mods` 传进来。`drawModifiersFor` 因此多了两条跳过：`layer === "L1"` 与
  `values.marks` 存在（按标记计价）
- 异议②的弃异**没有开新窗口**：档位塞进 `respond` 的 `choice`（`accept:2`）。
  「摸之前先弃几枚」没有可观察的中间态，多一个窗口就多一个要进快照隐私表的暂存态。
  §3.1 的 `drawDiscard(N)` 不一样——它摸完之后要让人看着手牌挑，那个中间态是真的

**第 3 步的落地记录（2026-08-02）**，三处与本文原计划不同：

- 窗口类型**改名** `shuffleDiscard` → `drawDiscard`，事件 `shuffleDiscardOpened` →
  `drawDiscardOpened`（`{ seat, picks, deadline }`）。忍戒/八门/合纵共用同一个窗口，
  顶着「洗牌」的名字语义错位。既有测试因此动了 8 行**名字**，行为断言一条没改
- 提交契约统一成 `{ choice: "discard", cardIds: [...] }`：**N = 1 也走多选**。
  组合不进 `legalActions`（八门弃 8 张就是 C(手牌,8) 上千条），引擎只给一条模板动作，
  客户端凑齐 N 张再提交，长度/在手/不重复三条由 `settleDrawDiscard` 硬校验。
  前端因此把手牌的多选态（原来只有并列♥4 用）接到了这个窗口上，坞里出「弃掉 m / N 张」
- 中间态换了地方：`ShufflePending.drawnId` 删掉，改成牌桌上的 `drawDiscard`
  （`{ seat, picks, drawnIds, resume }`）。`resume` 现在只有 `afterFace` 一支，
  第 4 步的忍戒在 `runResume` 里加第二支
- **摸吃层级、弃不吃**：摸那 N 张走 `drawCards`（活泼板那类 L2 对它生效），
  弃的张数照牌面的 N 走，牌堆枯竭时才按实际摸到的张数下调（03 §2）

**第 4 步的落地记录（2026-08-03）**，两处与本文原计划不同：

- L6 多了两样**数据**（都先落 02 §6 再动代码）：子效果新增 `procedure` 字段（这支后置程序
  叫什么，忍戒 = `draw_then_discard`），`values.L6` 用作**程序的参数**（忍戒 = 多摸上限 6）。
  没有名字的话 `layer: [L6]` 说不出改的是哪种执行方式，消费者只能按技能 id 分派——
  那正是本项目一路在避的东西。名字两处白名单：生成器的 `ENUMS.procedure` 与引擎的
  `PROCEDURES`，数据点名一支引擎没有的程序 → 生成时红 / 采集时抛，不静默跳过
- L6 由 `drawModifiersFor` **照常采集**（原计划以为要像 L1/L2 那样由调用方算好传进来）：
  它既不要 rng 也不按标记计价，`values` + `procedure` 就够了。采集口径从「`modifies` 含
  `draw_count`」放宽成「含 `draw_count` 或 `draw_procedure`」，一行
- 消费者是 `punish.ts::settle` 的吃牌路径：`resolution.count` 就是「最终值 N」，
  多摸 `min(N, 上限)` 走 `kind: "skill"`（P1：那几张不是惩罚），弃走 `drawDiscard` 窗口的
  新 resume 支 `afterPunish`——**交回合排在弃完之后**，U6 的声明按最终张数结算

**第 5 步的落地记录（2026-08-03）**，三处与本文原计划不同（本文原以为八门是「纯数据」）：

- **①不是纯数据**：卡面「不受其他技能影响」= 02 §7 的 **L1 替换**（与伤逝♥10 逐字同源的那句话），
  所以 ① 要一个 handler 把那条 L1 连同 `values.L1` 一起交给 `drawCards`，
  弃走 `drawDiscard` 的新 resume 支 `afterSkill`（弃完**回合还在自己手上**，还能出牌）。
  02 §6 因此补了一条例外：自己造成的摸牌，若明写「不受其他技能影响」就用 `layer: [L1]` 表达。
  这句的**范围**仍未裁定，读法与两条备选记在 **06-Q69**
- **②的五彩要有人赋**：新增 `window: turn_end` 的赋状态钩子 `skills/turn-end.ts`，
  数据侧新增 `grants` 字段（02 §6，状态名查 03 §4 的闭集）。落点在 `applyAction` 的出口，
  判据与 `settleUnoCall` 同源（「离场的那个座位」），不认技能 id
- **五彩的执行面一并建了**（本文没排期，但不建就是赋一个什么都不做的状态）：
  03 §4 那两句各一条——「只靠颜色相同的牌打不出」进 `legal.ts::playableFor`
  （出牌/并列首张/legalActions/U1 摸到即可打四条路统一走它），
  「变色牌不能改变颜色」进 `legal.ts::colorLocked`（出牌与洗牌③取消牌两条路共用），
  拒因 `color_locked`。前端把定色色块按它锁成一块。寄生♣9 / 古神赋同一个状态时不必再建

**第 6 步的落地记录（2026-08-03）**，本文把这一步当成一件事，实际是**两件**，只做完了一件：

- **②（无相应那半条）已建完**：新窗口 `drawOffer`（要 / 不要），要 → 接 §3.1 的 `drawDiscard`，
  两条路都回 `settleAfterFace` 接着跑这次出牌的收尾。S14 的「每次可选」因此是一个真窗口，
  不是自动摸——超时 = 不要。触发面按 03 §1：**功能牌 = +2 / 转 / 停**，+4 是变色牌不触发
- **连横的连击档**按 **01-S14b**（本次裁定）= 上一个**自己的**回合也打出过功能牌。
  牌桌上因此多了一本账 `funcPlay`（每座位「这回合 / 上回合」两个布尔）：出牌时置位，
  交回合时由第 5 步那个 `settleTurnEnd` 钩子轮转。**无条件记**——连横可能中途才亮出来
- **手上打空时不问**（fuzz 当场抓到的）：空手的摸 N 弃 N 是确定性空转（只能把刚摸的原样弃回去），
  而 01-U5 的补摸排在牌面效果之后，先开窗口会把牌桌停在「非终局却有人 0 张」上
- **①（相应 → 换牌）当天裁定后补齐**（06-Q70 的八条 + 01-S13b）：任一方**先亮出**那一刻问另一半
  一次（一锤定音，牌桌上一个 `alliance` 字段，缺席才问），相应即亮出并**整副手牌互换**；
  此后双方各自回合开始还能再换（`kind: active` + `window: turn_start`，**占 V7 主动条**——
  次数账、封印压制、`legalActions` 的可点性因此全走已有的主动脊梁，一条新逻辑都没加）。
  结盟与②互斥，双方的②同时关掉；任一方被封印则两人同时失去，解封恢复（只压制、不清值）
- 数据侧新增 `pairs_with`（02 §6，**双向对称**，生成器两头都查）：引擎靠它认亲，不认技能 id。
  `on_reveal` 也随之从「02 §2 的一个 kind」变成真有执行面的原语
- 顺带补上**前五步欠的前端文案**：`lib/skills.ts` 里给伤逝/异议/忍戒/八门/合纵/连横六张补了
  玩家版 L0/L1 与按钮文案，并加了一条闩（`lib/skills.test.ts`）——**清单从引擎的池子读**，
  以后再接线一个技能却忘了写文案，抽 3 选 1 的面板会摆出一张没说明的卡，那条测试当场红

**第 7 步的落地记录（2026-08-03）**：本文原打算按 `response` 窗口建，实际**整条路复用第 4 步的 L6**——
02 §7 那一行原文就写着「近卫：逐张交牌」，它本来就是后置程序。

- 引擎新增的只有一个窗口（`handOver`）与一个 30 行的 `skills/guard.ts`：门槛与张数从 `values` 读
  （`L6: 4` 门槛、`give: 1` 每段），采集走 `drawModifiersFor`，消费在吃牌路径**摸完之后**（01-P2）
- L6 修正因此从「带一个数」改成**带整张 `values`**：忍戒读 `L6`（上限），近卫读 `L6`（门槛）+ `give`。
  一个数装不下第二支程序，改在类型层比在每个消费者里查定义干净
- 「几张、在不在手上、有没有重复」三条硬校验抽成 `legal.ts::pickFromHand`，
  摸 N 弃 N 与近卫交牌共用；前端那套多选手牌的机件也一并泛化成「恰好 N」/「1 ‥ max」两档
- 边界按已定条款收口：链首是自己不成立（同 P8「不封自己」）、手上没牌不开窗口、
  上限还受手牌数限制、超时按不交、交完才交回合（U6 按最终张数结算）
- **公开面只有张数**：交出去的牌进了链首的手，内容只有他们两个知道（02 §8）

**第 8 步的落地记录（2026-08-03）**：本步最该守的是**别写成特例**，所以只加了**一个判据**。

- `skills/gift.ts::mustDrawWhenStuck(b, seat)` 是「此刻还必须摸吗」的**唯一出处**，
  `legalActions`（给不给「结束回合」）与 `endTurn`（没摸过想结束拒不拒）问的是同一个函数——
  少一处同源就会出现「坞里给了、引擎却拒」。**恋战**将来建执行面时问它即可，
  S17 的「神授优先于恋战」因此不必写成两条技能之间的互斥
- 「无牌可出」的口径复用 `playableFor`（含 03 §4 五彩那类状态限制），不另起判定
- 顺手补上 `endTurn` 缺的一条：惩罚轮里选了叠就只能叠（P3），此前那条路只在 `drawCard` 上拦着
- **前端零改动**：新动作就是既有的 `endTurn`，文案、槽位、事件一条都不用加——
  这是「不写特例」的直接回报
- **同日补完（06-Q71 已裁定）**，两件都按「不写特例」办：
  - **「一定要摸」的五种情形**（01-S17b）落成 `skills/gift.ts::drawIsForced` **一个函数**：
    ①惩罚看 `kind`、③他人技能看 `initiator`（与恩惠的 06-Q56 同口径）、②④⑤ 三种规则摸牌
    由调用方写 `DrawRequest.reason`。其余摸牌**每次都问**——「问一句」复用合纵/连横②那个
    `drawOffer` 窗口，并把它从 `skills/alliance.ts` **搬到摸 N 弃 N 的共用入口**
    （`openDrawDiscard` 先问、`drawAndDiscard` 真摸），于是洗牌②/八门/忍戒/合纵四条路径
    自动全覆盖，一处都不用单写
  - **01-V2 的亮出执行面**（`skills/reveal.ts`）：一张「窗口名 → 此刻成不成立」的表 +
    条件字段 `reveal_when`（神授 `{ hand_at_least: 11 }`）。V2b 两条口径：例外**只放宽
    「必须是自己的回合」**，反应窗口挂着时一律禁亮；**认不出的窗口名保守当作 `own_turn`**
    （契约的 `when_skipped`、偏折的 `when_challenged_uno` 执行面还没建，宁可少放行）

**第 9 步的落地记录（2026-08-03）**：本文原写「L2/L3 补 `scope` + 一个歌声槽」，实际**两样都没建**——
真正缺的是另外两件更通用的东西。

- **「作用域」早就在数据里了**：`targeting: global` 就是 06-Q62 说的全场生效，
  而 `drawModifiersFor` 本来就是按 `targeting` 收的。L2/L3 **不需要** `scope` 字段——
  那一层只做加总/连乘，作用域只影响「收不收这条」，不影响「怎么算」。
  真正要修的是另一处：`applies_to` 里那条「他人技能」的限定从前**写死在采集器里**、
  套在所有效果上，于是活泼板的「所有摸牌 +1」会漏掉自己造成的那些。改成数据里的
  `applies_to: [punish, skill_others]`（恩惠自己的卡面文字），采集器那条特例随之删掉
- **歌声槽做成了通用的「选项分支」**：数据侧 `option_of`（这条子效果是哪条主动的一个选项），
  牌桌侧 `Board.chosen`（按**技能 id** 存「现在选的是哪一支」）。于是：
  选歌 = 发动①并报那一支的 key（V7 的额度、窗口、压制全走已有的主动脊梁）；
  「哪一支生效」= 采集器上的一句 `optionLive`；06-Q66 的「后唱覆盖先唱」由「按技能 id 存一份」
  天然成立；心火♥Q 的三选一、宝藏★的四分支到时候照用，不必再造槽
- **行进曲不新建判定**：它与五彩「使用变色牌时不能改变颜色」是同一条规则，
  合并进 `legal.ts::colorLocked`（一个是状态给的、一个是歌声给的，判定只有一处）
- L3/L4 的修正形状（倍率 / 覆盖）这一步才第一次真的被数据用上；L4 的 `scope` 按
  `targeting` 推（歌声是 `global`，时神那支永久樱时雨将来标 `self` 即胜过它，02 §7 的口径）

**第 10 步的落地记录（2026-08-04）**：四条卡面挂在**四个已有的判定点**上，一条新判定都没建。

- 亮出定色 → 亮出钩子写进 `Board.chosen`（**与吟游的歌声共用那个槽**：吟游是玩家选的、
  专精是亮出时定死的）；「底牌」取摸牌堆最底下那张有色的牌（读法见收尾 spec 的 B2）
- 该色 +2 免摸 → `skills/specialty.ts::punishBase`，改的是**喂给 L0 的那个数**（06-Q68 明说
  L0–L6 一行不改）；逐段过滤、全免则**整个摸牌事件跳过**（不是摸 0，否则樱时雨会抬回 1）
- 可打任意数字 → `legal.ts::playableFor`（出牌四条路本来就都问它）
- 变色只能选你的色 → `legal.ts` 的 `colorLocked` 升成 `requiredColor`：
  五彩与行进曲要的是「维持跟色」、专精要的是「定成你的色」，三者一处判定
- 免疫五彩 → 数据里的 `immune` 字段 + `canGrantStatus` 一处，**谁来赋都挡得住**
  （八门②回合末那条赋状态一行没改就自动生效了）

### 5.1 每个技能的底线（沿用首批的三条纪律）

   （反向白名单会自动查「别人的手牌一个字节都没进快照」）

### 5.2 逐技能测试点

| 技能 | 必测 |
|---|---|
| 伤逝 | L1 命中即得最终值、**跳过 L2/L3/L4**；忽略贡献总和（用 `segments.length` 不是 `total`）；`replacedBy` 进事件 |
| 异议 | ①上家 +2/+4 → 反转 + 跳过，一次性用完不再给；②「异」标记每张 −1 落 L2；F3：可强制亮出、**不能**强制发动 |

| 八门 | ①一次性摸 8 弃 8 是**一个窗口**；②回合结束获五彩（走 `statuses`，三者互斥照旧）+ 所有摸牌 L2 +1 |
| 合纵/连横 | S13 亮出当下立刻决定，不选 = 无人相应；S14 无相应 → **每张**功能牌后一次摸弃，且**每次可选**（不是强制）；连横的「上回合也打出功能牌 → 摸 3 弃 3」要跨回合记账 |
| 近卫 | 只在 **≥4** 惩罚时给；每张 +2/+4 各一次机会（`segments` 逐段）；交的是**自己手牌**（非链上牌）给**链首**（P12）；链首是自己时的边界 |
| 神授 | 仅列情形必摸；否则无牌可出可**不摸直接结束**；恋战在场时**神授优先**（S17） |
